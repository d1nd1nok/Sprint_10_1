# Sprint_10_1

Дополнительный проект курса «Инженер по тестированию» (Яндекс Практикум): UI-автотесты для учебного сервиса [«Яндекс Маршруты»](https://qa-routes.education-services.ru/) на Selenium с Page Object Model и Allure-отчётом.

## Стек

- Python 3
- pytest
- Selenium WebDriver (Google Chrome)
- Allure (`allure-pytest`)

## Структура проекта

```
Sprint_10_1/
├── conftest.py              # фикстуры: driver, main_page (ввод адресов), choose_route_block, taxi_tariff_block
├── urls.py                  # URL сервиса
├── data.py                  # тестовые данные: адреса и описания тарифов по ТЗ
├── locators/                # локаторы — отдельный класс на каждый блок
│   ├── main_page_locators.py
│   ├── choose_route_locators.py

│   └── taxi_search_locators.py

│   ├── base_page.py         # BasePage — общие методы: поиск, клики, ввод, ожидания, наведение
│   ├── main_page.py         # MainPage — ввод адресов и точки на карте
│   ├── choose_route_page.py # ChooseRoutePage — блок выбора маршрута
│   ├── taxi_tariff_page.py  # TaxiTariffPage — блок заказа такси и тарифы
```

## Запуск

1. Установите Google Chrome.
2. Создайте виртуальное окружение и установите зависимости:

   ```bash
   python3 -m venv venv
   source venv/bin/activate
   pip install pytest selenium allure-pytest
   ```

3. Запустите тесты с сохранением результатов для Allure:

   ```bash
   pytest tests --alluredir=allure_results
   ```

4. Откройте отчёт (нужен установленный [Allure CLI](https://allurereport.org/docs/install/)):

   ```bash
   allure serve allure_results
   ```

## Задание

Напиши автотесты для учебного сервиса «Яндекс Маршруты». Ручной тестировщик передал сценарии — их нужно покрыть автотестами, применив Page Object Model и подключив Allure-отчёт.

### Подготовь проект

- Установи браузер Chrome.
- Создай в IDE новый проект `Sprint_n`.
- Подключи Selenium и Allure.
- Изучи использование `setTimeout` в консоли при тестировании, метод `hover` в Selenium и декоратор `@pytest.mark.xfail`.

### Тестовые сценарии

В программе есть два предустановленных адреса: **Хамовнический вал, 34** и **Зубовский бульвар, 37**. Использовать их можно в любой последовательности.

#### Отрисовка маршрута

- При вводе двух разных предустановленных адресов в поля «Откуда» и «Куда» на карте отображаются две точки — начало и конец маршрута.

#### Отрисовка блока с выбором маршрута

- При вводе двух разных предустановленных адресов в поля «Откуда» и «Куда» под выбором адресов отображается блок с выбором маршрута.
- При вводе одинакового адреса в поля «Откуда» и «Куда» отображается блок с выбором маршрута с текстом «Авто Бесплатно В пути 0 мин.».

#### Подготовка к заказу такси

*Предусловие: введены два разных предустановленных адреса в поля «Откуда» и «Куда».*

- При переключении между видами маршрута (Оптимальный / Быстрый) меняется активный таб и пересчитываются время и стоимость маршрута.
- При переключении на вид маршрута «Свой» меняется активный таб и становятся активны типы передвижения (Машина, Пешком, Такси, Велосипед, Самокат, Драйв).
- При выборе вида маршрута «Быстрый» активна кнопка «Вызвать такси».
- При выборе вида маршрута «Свой» и типа передвижения «Драйв» активна кнопка «Забронировать».

#### Заказ тарифа Такси

*Предусловие: введены два разных адреса, выбран вид маршрута «Быстрый», нажата кнопка «Вызвать такси».*

- Открывается форма заказа со всеми 6 тарифами по ТЗ, один из них активный.
- При наведении на иконку **i** в правом верхнем углу каждого тарифа отображается всплывающее окно с описанием тарифа, описание соответствует ТЗ.
- Под тарифами отображается блок с полями Телефон, Способ оплаты, Комментарий водителю, Требования к заказу.

#### Заказ тарифа Такси — полный сценарий

*Предусловие: то же, что в предыдущем разделе.*

1. Выбрать тариф «Рабочий», включить чекбокс «Столик для ноутбука», нажать «Ввести номер и заказать» — появляется окно ожидания машины (проверить элементы по ТЗ).
2. Дождаться окончания таймера поиска машины — отображается окно совершённого заказа (проверить элементы по ТЗ).
3. Нажать кнопку «Детали» в блоке «Ещё про поездку» — указана стоимость, которая была при выборе тарифа.
4. Нажать кнопку «Отмена» — окно закрывается.

### ТЗ и интерфейсы

#### 1. Блок начального экрана

- Карта в правой части экрана.
- Блок с вводом адресов: Откуда, Куда.

#### 2. Блок с выбором маршрута

- Виды маршрута: Оптимальный, Быстрый, Свой.
- Типы передвижения: Машина, Пешком, Такси, Велосипед, Самокат, Драйв.

- Тарифы: Рабочий, Сонный, Отпускной, Разговорчивый, Утешительный, Глянцевый.

- Кнопка «Ввести номер и заказать».

**Описание тарифов Такси:**

| Тариф | Описание |

| Сонный | Для тех, кто не выспался |

**Окно ожидания машины Такси:**

**Окно совершённого заказа Такси:**

- Тарифы: Повседневный, Походный, Роскошный.

**Описание тарифов Драйв:**

**Окно совершённого заказа Драйв:**

- Картинка выбранного тарифа и название тарифа над ней.
- Кнопка «Отменить».
- Блок с информацией: Адрес машины (адрес из поля «Откуда»), Ещё про поездку (Стоимость).

### Напиши тесты

- Опиши локаторы с помощью Page Object и создай для Page Object отдельный пакет.
- Для каждой страницы создай отдельный класс Page Object.
- Напиши тесты на Selenium и раздели их по тематике или функциональности. Не нужно создавать отдельный класс для каждого теста — тесты на одну функциональность объединяй в один класс.
- Все тесты должны лежать в директории `tests`.
- Проверь, что тесты запускаются.
- **В функционале есть баги.** Тесты должны соответствовать ТЗ, поэтому тесты, выявляющие баги, должны падать при прогоне.

### Сделай отчёт в Allure

Сгенерируй Allure-отчёт и запушь его в репозиторий.

## Критерии оценки

- Нейминг элементов корректный.
- Для каждого блока проверок тесты лежат в отдельном классе и отдельном тестовом модуле.
- Написаны тесты на функциональность «Отрисовка маршрута».
- Написаны тесты на функциональность «Отрисовка блока с выбором маршрута».
- Написаны тесты на функциональность «Подготовка к заказу такси».
- Написаны тесты на функциональность «Заказ тарифа Такси» и полный флоу.
- Сгенерирован Allure-отчёт, в репозиторий запушена только папка с отчётом.
- Для предусловий используются фикстуры.
- Все тесты независимы.
- Тестовые данные хранятся в отдельном модуле.
- В тестах и объектах страниц отсутствуют локаторы элементов.
- В тестах отсутствуют условия — тест всегда однозначен.
- В коде отсутствуют принты и закомментированный код.
- В коде отсутствуют слипы и неявные ожидания.
- В объектах страниц отсутствуют методы для работы с элементами других страниц.
- В тестах нет прямого обращения к `driver` — только через методы пейджей.
- Тесты с багами помечены декоратором `@pytest.mark.xfail`.
